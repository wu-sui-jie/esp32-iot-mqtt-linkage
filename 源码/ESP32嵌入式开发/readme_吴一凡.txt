================================================================================
一、实现了什么功能
================================================================================

────────────────────────────────────────────────────────────────
4 号板   sht30      温湿度传感器（纯传感器板）
────────────────────────────────────────────────────────────────
  板号 ID = 4         设备名 device = "sht30"

  · 每 5 秒通过 I2C 读一次 SHT30，温湿度合并成【一条】dat 报文上报
  · 温度和湿度各保留 1 位小数
  · 读取失败时【跳过本周期，不上报】—— 三道检查：
        I2C 有应答 / 字节数正好 6 / CRC 校验通过
    任一不过就丢弃，绝不把未初始化的内存当数据发出去
  · 本板没有可控设备，收到任何命令都不回执

  两个 key 是平台识别数据的依据，【不能改名】：
        temperature   温度   ℃      -40.0 ~ 125.0
        humidity      湿度   %RH     0.0 ~ 100.0

────────────────────────────────────────────────────────────────
5 号板   rgb        RGB 灯（执行器）
────────────────────────────────────────────────────────────────
  板号 ID = 5         设备名 device = "rgb"

  · 收到 set_color {r,g,b} → 四颗 WS2812 全部变成该颜色，并回执
  · r / g / b 各 0~255；三通道全 0 即熄灭（协议没定义单独的开关命令）
  · ack 的 param 回发实际颜色，平台据此确认
  · 参数非法 → 回 ack result:"fail"，【灯保持原状不动】
        缺任何一个通道 / 值不是数值 / 任一路越界 0~255
  · 【本板不做】亮度调节、动效（彩虹 / 呼吸等）
        协议 §5.5 只定义了 set_color，本次严格按协议
  · 【同板不做的设备】adc（电位器）、buzzer（蜂鸣器）
        使能宏保留为 0，不实现，也不用其他人做

────────────────────────────────────────────────────────────────
两块板都有
────────────────────────────────────────────────────────────────
  · 上电连 WiFi、连 MQTT
  · 连上后往 online 主题发 sys/online（Retain，带上电秒数）
  · 设置遗嘱 LWT：掉线时由服务器代发 sys/offline
  · 只订阅 cmd 主题，绝不订阅 report（防自回环）


================================================================================
二、收发哪些报文
================================================================================

主题前缀固定 202609_PP2/1        板号写 1，【不补前导零】

  下行（板子订阅）   202609_PP2/1/cmd        QoS 1              不保留
  上行（板子发布）   202609_PP2/1/report     QoS 0(dat) / 1(ack) 不保留
  上线（板子发布）   202609_PP2/1/online     QoS 1              【保留】

所有报文都是「信封 + 载荷」两层，信封固定 6 个字段，一个都不能少：
  {"ver":"1.0","type":"...","seq":n,"src":"板号","dst":0,"body":{...}}

下文示例为排版分行，实际发送换行随意。下面报文可直接复制粘贴。

──────────── 4 号板（sht30）发 ────────────
每 5 秒一条，QoS 0：
{"ver":"1.0","type":"dat","seq":88,"src":"4","dst":0,"body":{"device":"sht30","samples":[{"key":"temperature","value":26.5},{"key":"humidity","value":60.2}]}}

──────────── 5 号板（rgb）收 / 发 ────────────
收，QoS 1：
{"ver":"1.0","type":"cmd","seq":3,"src":"web","dst":5,"body":{"device":"rgb","action":"set_color","param":{"r":255,"g":0,"b":0}}}

回，QoS 1（seq 必须和收到的命令一致）：
{"ver":"1.0","type":"ack","seq":3,"src":"5","dst":0,"body":{"device":"rgb","action":"set_color","result":"ok","param":{"r":255,"g":0,"b":0}}}
失败时 result 为 "fail"，且不带 param。

──────────── 两块板都发 ────────────
上线，QoS 1 + Retain：
{"ver":"1.0","type":"sys","seq":1,"src":"5","dst":0,"body":{"device":"sys","event":"online","uptime":0}}
离线，由服务器代发遗嘱：
{"ver":"1.0","type":"sys","seq":2,"src":"5","dst":0,"body":{"device":"sys","event":"offline"}}

三、合并代码前必看
================================================================================

【1】必须换库，不能用 PubSubClient
      platformio.ini 的 lib_deps：
          删掉  knolleary/PubSubClient
          加入  256dpi/MQTT
      协议 §8.2 要求 QoS 1，PubSubClient 只能发 QoS 0。
      两个库 API 完全不同，不换库【编译都过不了】。

【2】回调函数里绝对不许 publish()
      arduino-mqtt 规定：在消息回调里调 publish / subscribe 会【死锁】。
      本模块做法是回调只解析 + 置标志，真正的发送在主循环里做。
      你要往回调里加任何逻辑，都必须照这个模式。

【3】my_config.h 里不能写 #define SSID
      协议附录 A 给的示例就是 #define SSID "..."，【照抄必编译失败】：
          error: expected unqualified-id before string constant
      原因：ESP32 的 WiFi.h 里有个方法就叫 SSID()，宏会把它替换掉。
      本工程用的是 WIFI_SSID / WIFI_PASSWORD。

【4】主题是精确字符串匹配，错一个字符就静默失联
      202609_PP2/1/report  和  202609_PP2/01/report
      是【两个毫不相干的主题】。写错了消息照发，但没人收得到，
      而且【不报任何错误】，极难排查。
      已知课堂例程 41-MQTT+JSON 写的是 202609_PP2/01（带前导零），
      那是单主题的另一套设计，不是本组协议，别抄。
      调试请订阅 202609_PP2/# （比协议写的 /1/# 更宽，
      这样才能看出有没有人发到了错主题上）。

【5】板子只订阅 cmd，绝不能订阅 report
      否则自己发出去的上报会被自己收到，自回环死循环。

【6】MQTTClient 必须显式放大缓冲区
      写成   MQTTClient client(1024, 1024);
      默认只有 128 字节，带 param 的报文会被【静默截断】。

【7】遗嘱 setWill 必须在 connect 之前调用
      连上之后再设无效，掉线时服务器不会代发 offline。

【8】mqtt_proto 有两份副本，改一份必须同步另一份
      同步后这样确认一致：
          diff sht30_board4/src/mqtt_proto.cpp rgb_board5/src/mqtt_proto.cpp
      所有依赖 MQTT 库的调用都只在这一个文件里，换库只改它。

四、怎么测
================================================================================

── MQTTX 设置 ──
  订阅主题    202609_PP2/#
  发布主题    202609_PP2/1/cmd        QoS 1      Retain 不勾
  Payload格式 Plaintext（先别用 JSON，避开本地校验拦截）
  服务器      yunyismart.tech  端口 1883   用户名密码【留空】

── 先看串口（115200），正常应依次出现 ──
  [proto] WiFi 已连接，IP = 192.168.x.x
  [proto] MQTT 已连接
  [proto] 已订阅 202609_PP2/1/cmd
  [proto] -> 202609_PP2/1/online : {...}
  卡在「连接 WiFi...」就是热点连不上。

── 4 号板不用发任何命令 ──
  插上电就每 5 秒吐一次。重点看小数是不是 1 位（26.5 而不是 26）。

── 5 号板逐条发（单行，直接复制）──

  红灯
  {"ver":"1.0","type":"cmd","seq":1,"src":"web","dst":5,"body":{"device":"rgb","action":"set_color","param":{"r":255,"g":0,"b":0}}}

  熄灭（全 0）
  {"ver":"1.0","type":"cmd","seq":2,"src":"web","dst":5,"body":{"device":"rgb","action":"set_color","param":{"r":0,"g":0,"b":0}}}

  越界 → 灯不动，ack result 为 fail
  {"ver":"1.0","type":"cmd","seq":3,"src":"web","dst":5,"body":{"device":"rgb","action":"set_color","param":{"r":300,"g":0,"b":0}}}

  缺通道 → 灯不动，ack result 为 fail
  {"ver":"1.0","type":"cmd","seq":4,"src":"web","dst":5,"body":{"device":"rgb","action":"set_color","param":{"r":255,"g":0}}}

  广播 dst=0 → 照样执行
  {"ver":"1.0","type":"cmd","seq":5,"src":"web","dst":0,"body":{"device":"rgb","action":"set_color","param":{"r":0,"g":0,"b":255}}}

  不是给本板的 dst=4 → 完全没反应
  {"ver":"1.0","type":"cmd","seq":6,"src":"web","dst":4,"body":{"device":"rgb","action":"set_color","param":{"r":255,"g":255,"b":0}}}

  版本不对 → 串口提示「协议版本不符」后忽略，不回执
  {"ver":"2.0","type":"cmd","seq":7,"src":"web","dst":5,"body":{"device":"rgb","action":"set_color","param":{"r":255,"g":0,"b":0}}}

── 验遗嘱 ──
  把板子【断电】（不是重启）。几秒后订阅区应收到 offline 报文。
