# 4 号板 · 温湿度传感器模块（sht30）

## 这个模块是干什么的

通过 I2C 读取 SHT30 传感器的温度和湿度，每 5 秒上报一次。**纯传感器板**，只管上报，不接收任何命令。

它上报的数据会驱动两个联动：

- 2 号板的风扇——温湿度过高时自动开风扇
- 7 号板的语音——超过阈值时播报「温度过高，当前 XX.X 度」

## 硬件与接线

| 项目 | 引脚 | 说明 |
|---|---|---|
| SHT30 SDA | GPIO21 | I2C 数据线 |
| SHT30 SCL | GPIO22 | I2C 时钟线 |
| VCC | 3.3V | |
| GND | GND | |

SHT30 的 I2C 地址是 `0x44`。

## 报文格式

### 上行数据（dat）

温度和湿度**合并在同一条报文**里发（协议 §5.4 明确要求，这样两个数据点的采集时刻一致，平台不会出现温度来自这一周期、湿度来自上一周期的情况）：

```json
{"ver":"1.0","type":"dat","seq":88,"src":"4","dst":0,"body":{"device":"sht30","samples":[{"key":"temperature","value":26.5},{"key":"humidity","value":60.2}]}}
```

两个 key **不能改名**，平台靠它们识别数据：

| key | 含义 | 单位 | 范围 |
|---|---|---|---|
| `temperature` | 温度 | ℃ | -40.0 ~ 125.0 |
| `humidity` | 湿度 | %RH | 0.0 ~ 100.0 |

都是保留 **1 位小数**。看订阅区时注意是不是 `26.5` 而不是 `26`——小数位数不一致会让平台画的曲线跳动。

### 上线

```json
{"ver":"1.0","type":"sys","seq":1,"src":"4","dst":0,"body":{"device":"sys","event":"online","uptime":12}}
```

## 怎么测

上电后串口每 5 秒打印一次：

```
[sht30] 温度 26.5 ℃  湿度 60.2 %RH
```

想快速看到数值变化，**用手捂住传感器**（体温加热，约 1~2 分钟能升到 30 ℃ 以上），或者对着它哈气提高湿度。这两个动作会同时触发 2 号板的风扇和 7 号板的播报。

### 读不到数据怎么办

本板有三道检查，任一不过就**跳过本周期、不上报**（串口会打印原因）：

1. I2C 有没有应答
2. 读到的字节数是不是正好 6
3. 温度与湿度的 CRC 校验是否通过

宁可少一条数据，也不上报一条错的——厂商例程没做 CRC 校验，不做的后果是读到错位数据也照算不误，会把莫名其妙的温湿度发出去。

## 本板驱动的联动

| 条件 | 谁动作 | 动作 |
|---|---|---|
| 温度 ≥ 30.0 ℃ 或 湿度 ≥ 80 % | 2 号板风扇 | 自动开风扇 |
| 回落到 28.0 ℃ / 75 % 以下并持续 10 秒 | 2 号板风扇 | 自动关风扇 |
| 温度 ≥ 30.0 ℃ | 7 号板语音 | 播报「温度过高，当前 XX.X 度」 |
| 湿度 ≥ 80 % | 7 号板语音 | 播报「湿度偏高，当前 XX%」 |

这些阈值分别在 2 号板和 7 号板自己的 `my_config.h` 里，本板不参与判断。

## 常见问题

| 现象 | 先查什么 |
|---|---|
| 串口一直打印读取失败 | SDA/SCL 接反；传感器供电；I2C 地址是否为 0x44 |
| 温度值明显不对 | 传感器贴在发热元件旁边；或者读到的其实是错位数据（CRC 会挡住大部分这种情况） |
| 数据不变化 | 传感器坏了或用的是 DHT11（那样需要改 `device` 名和驱动） |
| 风扇不联动 | 2 号板是否在线；它的 `SUB_EXTRA_REPORT` 是否为 1 |
