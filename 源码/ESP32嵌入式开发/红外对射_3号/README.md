# 3 号板 · 红外对射传感器模块（ir_beam）

## 这个模块是干什么的

一支红外发射管对着接收管，中间的光束被挡住就报警。**纯传感器板**，只管上报，不接收任何命令。

它上报两类信息：

- **事件（evt）**——光束被挡住 / 恢复正常，状态一变立刻发
- **数据（dat）**——累计遮挡次数，每次确认遮挡后加 1

---

## 硬件与接线

| 项目 | 引脚 | 说明 |
|---|---|---|
| 对射模块 DO | GPIO14 | 数字输入，高电平表示被遮挡 |
| VCC | 3.3V 或 5V | 按模块要求 |
| GND | GND | 必须与 ESP32 共地 |

如果实际模块的极性相反（遮挡时输出低电平），把 `src/my_config.h` 里的 `IR_ACTIVE_HIGH` 改成 0 即可，其余代码不用动。

## 单独调试与验证

这块板可以**脱离其他七块板单独验证**。需要的东西：本板 + USB 线 + MQTTX。

### 第 1 步：上电自检

烧录后打开串口监视器（波特率 115200），正常应该依次出现：

```
[proto] WiFi 已连接，IP = 192.168.x.x
[proto] MQTT 已连接
[proto] 已订阅 202609_PP2/1/cmd
[ir_beam] 初始化完成，初始状态：通畅
```

**卡住时按这个顺序排查**：

| 串口停在这里 | 说明 |
|---|---|
| `连接 WiFi` 后面一直点点点 | 热点名字或密码不对，改本模块 `my_config.h` 里的 `WIFI_SSID` / `WIFI_PASSWORD` |
| `MQTT 连接中...` 反复刷 | 服务器地址不对，或者网络没放行 1883 端口 |
| 没有最后那一行模块日志 | 外设接线问题，见下面「常见问题」 |

### 第 2 步：验证清单

| # | 检查项 | 怎么做 | 通过标准 |
|---|---|---|---|
| 1 | 板子活着 | 看串口 | 打印出上面那段启动日志 |
| 2 | 网络通 | 看串口 | 出现 `[proto] MQTT 已连接` 和订阅成功 |
| 3 | 能收命令 | 不需要发命令（纯传感器） | — |
| 4 | 能上报 | 订阅区收到本板的 evt | 用手挡一下光路，应立刻收到 `blocked`；移开收到 `clear` |
| 5 | 联动（可选） | 不适用（本板是传感器，不驱动别的板） | — |

这一轮走完，说明这块板本身没有问题了。具体的报文内容和预期现象在下面各节里。
重点确认：挡光/移开是不是都能立刻上报，30 秒有没有心跳。

## 报文格式

### 上行事件（evt）

**光束被遮挡**——等级 2（警告），状态一变立刻发

```json
{"ver":"1.0","type":"evt","seq":58,"src":"3","dst":0,"body":{"device":"ir_beam","event":"blocked","level":2}}
```

**光束恢复**——等级 0（恢复）

```json
{"ver":"1.0","type":"evt","seq":59,"src":"3","dst":0,"body":{"device":"ir_beam","event":"clear","level":0}}
```

### 上行数据（dat）

**累计遮挡次数**——每次确认遮挡后加 1（协议表 20 的扩展数据点）

```json
{"ver":"1.0","type":"dat","seq":60,"src":"3","dst":0,"body":{"device":"ir_beam","samples":[{"key":"count","value":1}]}}
```

### 上线

```json
{"ver":"1.0","type":"sys","seq":1,"src":"3","dst":0,"body":{"device":"sys","event":"online","uptime":12}}
```

## 上报节奏（协议表 19 的规定）

| 参数 | 值 | 作用 |
|---|---|---|
| 去抖 | 50 ms | 状态要连续稳定这么久才认——手抖、飞虫、气流都会让接收管瞬间误判 |
| 限流 | 500 ms | 同一状态半秒内不重复上报，防止刷屏 |
| 心跳 | 30 秒 | 状态一直不变时也定期重发一次当前状态 |

**心跳是干什么用的**：如果只在变化时上报，那么"状态没变"和"这块板掉线了"在平台上看起来一模一样。定期心跳让平台能区分这两种情况。

另外 MQTT 连接成功（含断线重连）之后，本板会立刻补报一次当前状态，不用等下一次变化或心跳。

---

## 怎么测

1. 上电后串口应该打印 `红外初始状态: 通畅` 或 `遮挡`
2. 用手或纸板挡住光路 → 订阅区立刻出现 `blocked` 事件
3. 移开 → 出现 `clear` 事件，同时 `count` 加 1
4. 什么都不动，等 30 秒 → 应该看到一条心跳 evt（重复当前状态）

### 本板的联动作用

3 号板自己是传感器，但它的事件会驱动 1 号板：

| 本板上报 | 1 号板（舵机）的动作 |
|---|---|
| `blocked` | 转到 0° |
| `clear` | 回到 90° |

所以测联动时，挡一下光路就应该看到舵机转过去。

## 可调参数

都在 `src/my_config.h`：

```c
#define IR_PIN 14                // 信号引脚
#define IR_ACTIVE_HIGH 1         // 1 = 遮挡时高电平；极性相反就改成 0
#define IR_DEBOUNCE_MS 50UL      // 去抖时间
#define IR_MIN_GAP_MS 500UL      // 同一状态的限流
#define IR_HEARTBEAT_MS 30000UL  // 心跳周期
```

## 常见问题

| 现象 | 先查什么 |
|---|---|
| 一直是"遮挡"或一直是"通畅" | 光路没对准；`IR_ACTIVE_HIGH` 极性填反了 |
| 过一会儿就报一次遮挡 | 光路没对准导致间歇性断开，重新对准发射管和接收管 |
| 一点变化都没有 | 供电和共地；信号线是不是 GPIO14 |
| 舵机不跟着转 | 1 号板是不是在线；1 号板的 `SUB_EXTRA_REPORT` 是否为 1 |
