# 7 号板 · 智能语音播报模块（tts）

## 这个模块是干什么的

把文字念出来。它比别的执行器多一件事：**不只听平台命令，还旁听其他板子在干什么**，主动把系统运行情况播报出来。

两条播报来源：

| 来源 | 说明 |
|---|---|
| 平台下发 | 收到 `play_text` 就把文本念出来 |
| 本地联动 | 自己订阅 report 与 online，判断该播什么，不经过平台 |

---

## 三层播报结构

这是本模块的核心设计。板子把话说成三类，按优先级排：

### 第一层 · 事件即时播报

状态一变就出声。这一层包含：

| 触发源 | 播报内容 | 等级 |
|---|---|---|
| 6 号 flame `detected` | 「警告，检测到火焰」 | 3 紧急 |
| 6 号 flame `clear` | 「火焰警报已解除」 | 0 恢复 |
| 3 号 ir_beam `blocked` | 「注意，检测到遮挡」 | 2 警告 |
| 3 号 ir_beam `clear` | 「遮挡已恢复」 | 0 恢复 |
| 1 号 servo `auto_move` | 「舵机已转到遮挡位」 | 1 提示 |
| 1 号 servo `auto_home` | 「舵机已复位」 | 1 提示 |
| 2 号 fan `auto_on` | 「环境超标，已自动开启风扇」 | 1 提示 |
| 2 号 fan `auto_off` | 「环境恢复正常，已关闭风扇」 | 0 恢复 |
| 5 号 rgb `scene_light` | 「光线过暗，已开启照明」 | 1 提示 |
| 任意板 sys `online` | 「X 号设备已上线」 | 1 提示 |
| 任意板 sys `offline` | 「X 号设备已离线」 | 2 警告 |
| 1 号 servo 的 ack（平台命令） | 「舵机已转到 X 度」 | 1 提示 |

### 第二层 · 阈值告警

数据越界时播报，带冷却防止刷屏：

| 条件 | 播报内容 |
|---|---|
| 4 号板温度 ≥ 30.0 ℃ | 「温度过高，当前 XX.X 度」 |
| 4 号板湿度 ≥ 80 % | 「湿度偏高，当前 XX%」 |
| 8 号板光照 < 50 lx | 「光线过暗，请注意」 |

### 第三层 · 周期数据汇总

**每 30 秒**把各模块的最新值合成一句话念一遍：

> 「环境汇总，温度26.5度，湿度60%，光照125勒克斯，对射通畅，火焰正常」

###### 为什么要有这一层

前两层都是"出了事才说话"，正常范围内的数据一句都不播，于是听不到系统整体的状况。但**逐条播报在物理上做不到**：八块板合起来每秒产生一两条报文，而语音念一句话要两三秒，数据产生的速度是播报能力的五到七倍，排多长的队都会越播越滞后。

所以第三层不做队列，只做**快照**——每个数据源只留最新值，新数据覆盖旧的。念的永远是当前值。

###### 几个细节

- **空闲才播**：正在播告警或有告警在排队时，汇总自动让路，一空闲立刻补上
- **设备关掉就不念了**：每个数据源有新鲜度窗口（温湿度 15 秒、光照 10 秒、对射 70 秒、火焰 15 秒），超过窗口没收到新数据，那一项自动从句子里消失，不会一直念一块已经断电的板子最后报上来的数
- **没有数据的模块整段省略**，不念"未知"，掉一块板也能听完整句

## 用 MQTTX 调试

### 连接设置

| 参数 | 值 |
|---|---|
| 服务器 | `yunyismart.tech` |
| 端口 | `1883` |
| 用户名 / 密码 | 留空 |
| 订阅主题 | `202609_PP2/#` |
| 发布主题 | `202609_PP2/1/cmd` |
| QoS | 1 |
| Payload 格式 | Plaintext |

### 下行命令（平台下发播报）

**基本播报**

```json
{"ver":"1.0","type":"cmd","seq":1,"src":"web","dst":7,"body":{"device":"tts","action":"play_text","param":{"text":"欢迎使用物联网系统"}}}
```

**验证数字与中文混排**

```json
{"ver":"1.0","type":"cmd","seq":2,"src":"web","dst":7,"body":{"device":"tts","action":"play_text","param":{"text":"当前温度26.5度"}}}
```

**超长文本**（会截断到 100 字节以内，注意听结尾有没有被切掉）

```json
{"ver":"1.0","type":"cmd","seq":3,"src":"web","dst":7,"body":{"device":"tts","action":"play_text","param":{"text":"这段文本故意写得很长很长很长很长很长很长很长很长很长很长很长很长很长很长很长很长很长很长很长很长很长很长很长很长"}}}
```

**空文本**——不播报，回执 result 为 fail

```json
{"ver":"1.0","type":"cmd","seq":4,"src":"web","dst":7,"body":{"device":"tts","action":"play_text","param":{"text":""}}}
```

### 上行回执

ack 的语义是"文本已下发至语音模块，开始播报"，**不等播完就回**（协议表 14）：

```json
{"ver":"1.0","type":"ack","seq":1,"src":"7","dst":0,"body":{"device":"tts","action":"play_text","result":"ok"}}
```

### 测联动播报（不用真实的板）

往 `202609_PP2/1/report` 发，**src 必须是被模拟板的号**：

模拟火焰（应该播「警告，检测到火焰」）：

```json
{"ver":"1.0","type":"evt","seq":31,"src":"6","dst":0,"body":{"device":"flame","event":"detected","level":3}}
```

紧接着再发一遍同样的（这就是 6 号板每 5 秒的重发）——**应该不播报**，串口打印"同一轮火焰的重发上报，不重播"。

模拟火焰解除：

```json
{"ver":"1.0","type":"evt","seq":32,"src":"6","dst":0,"body":{"device":"flame","event":"clear","level":0}}
```

**重点**：灭火后马上再点火，应该【立即】播报，不会被冷却压住。

模拟温度超标（应该播「温度过高，当前 32.5 度」）：

```json
{"ver":"1.0","type":"dat","seq":88,"src":"4","dst":0,"body":{"device":"sht30","samples":[{"key":"temperature","value":32.5},{"key":"humidity","value":60.2}]}}
```

模拟遮挡、光照过暗、设备上下线同理，把 src 改成 3 / 8 / 任意板号即可。设备上下线要发到 `202609_PP2/1/online` 并勾上 Retain。

### 抢占测试

趁它正在念「光线过暗」时马上发一条火焰告警——应该立即打断，改念火焰。平台下发的命令等级最高，任何时候都能盖过本地联动播报。

## 硬件与接线

| 项目 | 参数 |
|---|---|
| 模块串口 | Serial2，ESP32 的 GPIO17 → 模块 RXD，GPIO16 → 模块 TXD |
| 串口参数 | **115200，8 位数据，偶校验，1 位停止位（8E1）** |
| 供电 | 模块要独立供电 |

**波特率或校验位写错的现象都是"完全没声音"，而且不报任何错**，是最难查的一类故障，这两个值别随手改。

下发帧格式（模块要求的固定格式）：

```
0xFD | 长度高字节 | 长度低字节 | 0x01 | 0x01 | GB2312 文本
```

长度填的是**字节数**不是字符数：一个汉字在 GB2312 里占 2 字节，"欢迎"是 4 字节，长度字段写 6。

## 播报队列与优先级

| 等级 | 谁在用 |
|---|---|
| 4 | 平台下发的命令（最高，人点的那一下必须能盖过联动） |
| 3 | 火焰告警 |
| 2 | 遮挡、温度过高、设备离线 |
| 1 | 提示类：光照过暗、上线、舵机与风扇的联动动作、周期汇总 |
| 0 | 恢复类：火焰解除、遮挡恢复 |

正在播报时来了更高等级的任务会**立即打断**改播新的；同等级或更低就排队。队列最多存 6 条，满了丢等级最低的一条。内容完全相同的句子不会重复入队。

## 可调参数

都在 `src/my_config.h`：

```c
#define TTS_RX_PIN 16 / TTS_TX_PIN 17   // 串口引脚
#define TTS_BAUD 115200                  // 波特率，别改
#define TTS_MAX_BYTES 100                // 单条播报长度上限（GB2312 字节）
#define TTS_QUEUE_LEN 6                  // 队列长度

#define TEMP_HIGH 30.0f                  // 温度播报阈值
#define HUMI_HIGH 80.0f                  // 湿度播报阈值
#define LIGHT_LOW 50.0f                  // 光照播报阈值

#define COOLDOWN_ALARM_MS 30000UL        // 警告类冷却
#define COOLDOWN_INFO_MS 60000UL         // 提示类冷却
#define COOLDOWN_FLAME_MS 3000UL         // 火焰抖动地板（短，保证点火就能响）

#define TTS_SUMMARY_ENABLE 1             // 周期汇总开关，改 0 就完全不播
#define SUMMARY_PERIOD_MS 30000UL        // 汇总周期
#define BOARD_EVENT_MERGE_MS 2000UL      // 上下线合并窗口
#define SNAP_TIMEOUT_SHT30_MS 15000UL    // 各数据源的新鲜度窗口
```

**想让它安静一点**：把 `TTS_SUMMARY_ENABLE` 改成 0，或者把几个冷却时间调大。
**想让它更灵敏**：调小 `COOLDOWN_FLAME_MS`（别超过 5000），或者调小各阈值。

## 常见问题

| 现象 | 先查什么 |
|---|---|
| 完全没声音 | 8E1 与 115200 两个参数；模块供电；TX/RX 是不是接反了 |
| 有声音但念的是杂音 | 编码转换有问题，检查是不是 UTF-8 转 GB2312 那一步 |
| 播到一半重启 | 模块供电不足 |
| 上下线不播报 | 是不是合并窗口内连着变了好几次；串口会打印登记与合并过程 |
| 设备关了还在念它的数据 | 等对应的新鲜度窗口过去（温湿度 15 秒、光照 10 秒）；窗口值在 `my_config.h` |
| 点火时有时不响 | `COOLDOWN_FLAME_MS` 被改大了，默认 3 秒 |
