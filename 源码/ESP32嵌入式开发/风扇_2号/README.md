# 2 号板 · 继电器（风扇）模块（fan）

## 这个模块是干什么的

用继电器控制一个风扇的开关。两件事同时在做：

1. **听平台命令**——平台下发开/关，继电器吸合或断开，动作后回执确认
2. **听温湿度**——4 号板报来的温度或湿度超标时，自己把风扇打开，不经过平台

风扇只有"全速转"和"停"两种状态，没有调速档位（协议表 9 只定义了开与关）。

---

## 硬件与接线

| 项目 | 引脚 | 说明 |
|---|---|---|
| 继电器信号线 | GPIO14 | 经板载 S8050 三极管驱动 |
| 继电器输出 | 端子 P1 | 风扇接这里，注意风扇的供电独立于 ESP32 |

继电器模块自己带三极管驱动和续流二极管，ESP32 这一侧只需要给一个高低电平。

## 报文格式与逐条测试

### 下行命令（你发给板子）

**开风扇**

```json
{"ver":"1.0","type":"cmd","seq":1,"src":"web","dst":2,"body":{"device":"fan","action":"set_power","param":{"on":true}}}
```

**关风扇**

```json
{"ver":"1.0","type":"cmd","seq":2,"src":"web","dst":2,"body":{"device":"fan","action":"set_power","param":{"on":false}}}
```

**布尔值不加引号**——协议表 5 明确规定开关类参数用 JSON 原生布尔值。写成 `"on":"true"`（带引号）会被当成参数非法拒绝，风扇保持原状态并回 `fail`。

**缺参数的残缺报文**也会被拒绝：

```json
{"ver":"1.0","type":"cmd","seq":3,"src":"web","dst":2,"body":{"device":"fan","action":"set_power"}}
```

> 这条会被拒绝是刻意的：如果"缺了就按 false 处理"，一个残缺报文就会把正在转的风扇误关掉，比报错更糟。

### 上行报文（板子发出来的）

**回执**（param 回发执行后的实际状态）

```json
{"ver":"1.0","type":"ack","seq":1,"src":"2","dst":0,"body":{"device":"fan","action":"set_power","result":"ok","param":{"on":true}}}
```

**联动开关风扇**

```json
{"ver":"1.0","type":"evt","seq":20,"src":"2","dst":0,"body":{"device":"fan","event":"auto_on","level":1}}
{"ver":"1.0","type":"evt","seq":21,"src":"2","dst":0,"body":{"device":"fan","event":"auto_off","level":0}}
```

**上线**（发到 `202609_PP2/1/online`，Retain）

```json
{"ver":"1.0","type":"sys","seq":1,"src":"2","dst":0,"body":{"device":"sys","event":"online","uptime":12}}
```

## 联动行为

本板订阅了 report 主题来听 4 号板的温湿度数据：

| 条件 | 动作 |
|---|---|
| 温度 ≥ **30.0 ℃** 或 湿度 ≥ **80 %** | 自动开风扇，并发 `auto_on` |
| 两者都回落到 28.0 ℃ / 75 % 以下，**并持续 10 秒** | 自动关风扇，并发 `auto_off` |

### 为什么开和关的阈值不一样

这是**迟滞**。如果开关用同一个阈值（比如都是 30 ℃），读数在 30 ℃ 上下浮动时继电器会一秒钟吸合好几次，既吵又伤触点。开 30、关 28，中间 2 ℃ 是缓冲区。

### 为什么关风扇要等 10 秒

传感器偶尔会跳一个数（I2C 受扰、热源晃动），单次跳数不该让风扇启停。条件持续正常 10 秒才关，抖动造成的短暂越界就被吞掉了。

### 平台命令 vs 联动

平台手动开关风扇**永远有效**，联动不会去覆盖它。联动只在"环境条件发生变化"的那一刻动作，所以演示时可以随时手动控制。

### 想现场调阈值

改 `src/my_config.h`：

```c
#define LINK_TEMP_ON 30.0f    // 温度达到多少开风扇
#define LINK_TEMP_OFF 28.0f   // 降到多少以下算恢复正常
#define LINK_HUMI_ON 80.0f    // 湿度达到多少开风扇
#define LINK_HUMI_OFF 75.0f   // 降到多少以下算恢复正常
#define LINK_FAN_HOLD_MS 10000UL  // 恢复正常后持续多久才关
```

### 没有 4 号板时怎么测联动

用 MQTTX 往 `202609_PP2/1/report` 发（**src 必须写 4**，否则会被当成别的板发的）：

```json
{"ver":"1.0","type":"dat","seq":88,"src":"4","dst":0,"body":{"device":"sht30","samples":[{"key":"temperature","value":32.5},{"key":"humidity","value":60.2}]}}
```

发完风扇应该立刻转起来，同时订阅区能看到 `auto_on` 事件。

## 常见问题

| 现象 | 先查什么 |
|---|---|
| 风扇不转 | 继电器输出端子的接线；风扇自己的供电 |
| 继电器一直"啪嗒啪嗒"响 | 是不是把开/关阈值改成一样了，加回迟滞 |
| 发命令没反应 | `dst` 是不是 2 或 0；`device` 是不是 `fan` |
| 上电时继电器吸合一下 | 正常，上电瞬间电平未稳定；本板初始化后就是停止状态 |
