# 6 号板 · 火焰传感器模块（flame）

## 这个模块是干什么的

用火焰传感器检测有没有明火。**纯传感器板**，只管上报，不接收任何命令。

它上报两类信息：

- **事件（evt）**——检测到火焰 / 火焰消失，状态一变立刻发，火焰持续期间每 5 秒重发一次
- **数据（dat）**——火焰红外强度原始值，每 1 秒一条

6 号板一报火焰，5 号板就会亮起多彩循环灯并让蜂鸣器间歇报警，7 号板会播报「警告，检测到火焰」。

---

## 硬件与接线

| 项目 | 引脚 | 说明 |
|---|---|---|
| 火焰传感器 AO | GPIO33 | 模拟量输出，用这个 |
| 火焰传感器 DO | GPIO14 | 数字量输出，**本版不用** |
| VCC / GND | 3.3V / GND | |

本版只用模拟量 AO 判断，不依赖数字量 DO。这样不管模块是高有效还是低有效都适用。

## 单独调试与验证

这块板可以**脱离其他七块板单独验证**。需要的东西：本板 + USB 线 + MQTTX。

### 第 1 步：上电自检

烧录后打开串口监视器（波特率 115200），正常应该依次出现：

```
[proto] WiFi 已连接，IP = 192.168.x.x
[proto] MQTT 已连接
[proto] 已订阅 202609_PP2/1/cmd
[flame] AO 基线校准中（请勿点火），2000 毫秒...
[flame] 基线 IO33=1876  判定阈值=3000
[flame] 初始化完成，当前状态：无火
```

**卡住时按这个顺序排查**：

| 串口停在这里 | 说明 |
|---|---|
| `连接 WiFi` 后面一直点点点 | 热点名字或密码不对，改本模块 `my_config.h` 里的 `WIFI_SSID` / `WIFI_PASSWORD` |
| `MQTT 连接中...` 反复刷 | 服务器地址不对，或者网络没放行 1883 端口 |
| 没有最后那一行模块日志 | 外设接线问题，见下面「常见问题」 |

### 第 2 步：验证清单

| # | 检查项 | 怎么做 | 通过标准 |
|---|---|---|---|
| 1 | 板子活着 | 看串口 | 打印出上面那段启动日志 |
| 2 | 网络通 | 看串口 | 出现 `[proto] MQTT 已连接` 和订阅成功 |
| 3 | 能收命令 | 不需要发命令（纯传感器） | — |
| 4 | 能上报 | 订阅区收到本板的 dat | 什么都不做，每秒一条 intensity；打火机靠近则出现 detected 事件 |
| 5 | 联动（可选） | 不适用（本板是传感器，只报数） | — |

这一轮走完，说明这块板本身没有问题了。具体的报文内容和预期现象在下面各节里。
重点确认：打火机能不能触发、移开能不能解除。

## 报文格式

### 上行事件（evt）

**检测到火焰**——等级 3（紧急）

```json
{"ver":"1.0","type":"evt","seq":31,"src":"6","dst":0,"body":{"device":"flame","event":"detected","level":3}}
```

**火焰消失**——等级 0（恢复）

```json
{"ver":"1.0","type":"evt","seq":32,"src":"6","dst":0,"body":{"device":"flame","event":"clear","level":0}}
```

**持续期间的重发**：火焰还在烧的时候，每 5 秒重发一次 `detected`，这样平台即使漏收一两条也能确认告警仍在持续。重发用的 seq 是新的，但内容和第一次一样。

### 上行数据（dat）

**火焰强度**——0~4095 的原始值，每 1 秒一条

```json
{"ver":"1.0","type":"dat","seq":33,"src":"6","dst":0,"body":{"device":"flame","samples":[{"key":"intensity","value":3120}]}}
```

强度上报和事件上报是独立的：即使没触发告警，强度也照常上报，平台可以据此画曲线或者自己设更灵敏的阈值。

### 上线

```json
{"ver":"1.0","type":"sys","seq":1,"src":"6","dst":0,"body":{"device":"sys","event":"online","uptime":12}}
```

## 检测原理（决定了你该怎么测）

代码**不用绝对阈值，而用"相对基线的偏移"**。

不同环境下无火时的静止读数差别很大——光照、电源、传感器个体差异都会影响，写死一个绝对阈值换个场合就失效。所以：

1. **开机先校准 2 秒**，采样取平均得到"无火基线"
2. 之后只要读数偏离基线超过 `FLAME_THRESHOLD`（默认 3000）就判为有火焰

**这意味着：上电后的 2 秒内不要有火源**，否则基线会被抬高，之后就不灵了。串口会提示：

```
[flame] AO 基线校准中（请勿点火），2000 毫秒...
[flame] 基线 IO33=1876  判定阈值=3000
```

---

## 怎么测

1. **上电时保持 2 秒无火**，等串口打印出基线值
2. 用打火机在传感器前 **10~20 cm** 处打火 —— 距离太近会一直触发，太远可能到不了阈值
3. 订阅区应该立刻出现 `detected` 事件，串口打印：

```
[flame] >>> 检测到火焰 <<<（IO=3820 偏离=1944 阈值=3000）
```

4. 移开打火机 → 出现 `clear` 事件
5. **演示要点**：灭火后马上再点火，应该立刻重新播报，不会被冷却压住

### 想看强度曲线

订阅区里每 1 秒一条 `intensity`。无火时数值接近基线，有火时明显抬高。如果无火时的读数就已经很接近阈值，说明环境光太强或者传感器离热源太近。

## 上报参数（协议表 19 的规定）

| 参数 | 值 | 作用 |
|---|---|---|
| 去抖 | 50 ms | 火焰跳动会让读数抖，稳定后才认 |
| 限流 | 500 ms | 同一触发事件半秒内不重复上报，防刷屏 |
| 重发 | 5 秒 | 火焰持续期间定期重发 detected，防平台漏报 |
| 强度上报 | 1 秒 | 独立的周期上报 |

**限流不会丢事件**：如果状态跳变正好落在 500 毫秒的限流窗口里，代码会记下来等窗口过去补发，最多迟半秒，但不会像以前那样凭空消失（状态跳变一块板只发生一次，丢了就没有第二次机会）。

---

## 怎么调灵敏度

改 `src/my_config.h`：

```c
#define FLAME_THRESHOLD 3000   // 偏离基线超过它就判为有火，调小更灵敏
#define FLAME_CALIBRATE_MS 2000UL  // 基线校准时长
#define FLAME_RESEND_MS 5000UL     // 持续期间的重发间隔
#define FLAME_DAT_PERIOD_MS 1000UL // 强度上报周期
```

调小 `FLAME_THRESHOLD` 更灵敏但更容易误报；调大则相反。

## 常见问题

| 现象 | 先查什么 |
|---|---|
| 一点火就报、移开还报 | 校准期间有火源，**重新上电并保持 2 秒无火** |
| 打火机点了但没反应 | 距离太远（拉到 10 cm 内试试）；或者阈值调得太大 |
| 无火时读数就很接近阈值 | 环境光太强、传感器旁边有热源，换个位置或重新校准 |
| 火焰灭了 5 号板还在报警 | 看本板串口：还在打印"火焰持续中"说明确实仍判为有火（调阈值或重新校准）；不再打印说明是 5 号板的超时兜底在起作用，15 秒内会停 |
